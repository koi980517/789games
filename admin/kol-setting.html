现有网红规则 · 5ji-wanghong

现有后台逻辑，2026-11-11 QA 实测，保持不变
网红（名单内会员）→ 邀请好友 → 一级：上级代理 5ji-wanghong→ 邀请好友 → 二级：上级代理 5-ji-agent→ 三级及以后：5-ji-agent
  • 一级进 5ji-wanghong名单内会员用邀请好友链接（/invite/会员ID）拉来的新会员，上级代理 = 5ji-wanghong，计入它的直属会员和团队数。
  • 只管一层，不往下传一级会员不在名单内时，他再拉来的人归入 5-ji-agent。实测：M1 在名单 → M4 进 5ji-wanghong；M4 不在名单 → M5 进 5-ji-agent。
  • 只影响之后的新注册归属在注册那一刻决定。加入、停用或移出名单，都不会移动已注册的会员。
  • 网红本人不变加入名单不改网红自己的上级代理和团队数，网红团队数仍为 0。
  • 代理邀请码不受影响名单只管会员的「邀请好友」路径。代理邀请码（/?vip=邀请码）照常归到对应代理。
  • 所有网红共用一个代理目标代理固定为 5ji-wanghong，不能为每个网红指定代理。要看某个网红带来的人，按「邀请人」筛选。

全链路网红规则 · all-life-wanghong

新增，与现有网红逻辑完全分开
全链路网红（全链路名单内）→ 邀请好友 → 一级 · all-wanghong-1→ 二级 · all-wanghong-2→ N 级 · all-wanghong-n（都在 all-life-wanghong 下）
  • 一级到 N 级都进 all-life-wanghong全链路网红邀请的整条链，不限层级，上级代理都是 all-life-wanghong，并写入字段 all_life_wanghong = 网红 ID。
  • 层级标记 all-wanghong-n，注册时写入只看直接邀请人：邀请人在全链路名单 → 新会员标记 all-wanghong-1；邀请人带 all-wanghong-n → 新会员标记 all-wanghong-(n+1)，继承 all_life_wanghong。标记在注册时写入，之后不变。
  • 先查全链路，再走现有规则未命中全链路时，才看直接邀请人是否在现有网红名单（→ 5ji-wanghong），否则 → 5-ji-agent。
  • 两套互不读取全链路只认全链路名单和 all_life_wanghong 字段；现有规则只认现有名单和 wanghong 字段。两份名单不互斥，同一会员可同时在两份里，此时他邀请的人按全链路处理。
  • 加入前的下线：补写标记网红通常先注册、后加入名单。添加时可勾选「同时补写已有下线」：顺着邀请关系往下逐层写 1、2…n，网红字段写成他；原来归上层网红的也改归他。只改标记，不改上级代理、佣金和历史报表（建议，待确认）。
  • 统计都归最近的网红带 all-wanghong-n 的会员自己成为全链路网红后，他下面的人从 all-wanghong-1 重新算，统计归他。
  • 代理邀请码不受影响代理邀请码和自然注册不走全链路判断。全链路开关关闭时只走现有规则。
