# 【789games】第三方登录入口后台开关 PRD v1.0

2026-11-27 · Koi　|　原型：`third-login-switch-prototype-v1.0.html`

## 1. 背景与范围
- 现状：登录 / 注册弹窗「or continue with」区固定显示 Google、Facebook、Telegram 三个按钮，无法单独关闭。
- 目标：运营在后台按站点单独控制三个按钮显示 / 隐藏，即时生效，H5 与 App 一致。
- 包含：登录 / 注册弹窗的三方按钮。不包含：账户安全页的绑定入口、Apple 登录、三方登录流程本身。
- 站点：789games 与 789bingo 共用后端，配置按站点分开存。

## 2. 前台规则
| 编号 | 场景 | 表现 |
|---|---|---|
| L1 | 三个都开 | 与现网一致，顺序 Google / Facebook / Telegram |
| L2 | 部分关闭 | 只显示开启的按钮，剩余按钮居中，间距不变 |
| L3 | 全部关闭 | 「or continue with」分隔线和按钮区整块隐藏，下方 Responsible Gaming 上移 |
| L4 | LAST 角标 | 上次登录方式被关闭时不显示角标，不转移到其他按钮 |

- 读取时机：H5 每次打开登录弹窗请求一次配置；App 启动和打开弹窗时请求。
- 接口失败：按「三个都开」兜底，不阻断手机号登录。
- 关闭后：后端同时拒绝该方式的登录请求（防旧页面 / 旧包直接调用），返回 `This login method is unavailable. Please log in with your mobile number.`

## 3. 后台配置
- 菜单：系统设置 → 第三方登录配置（新增）
- 页面：站点切换（789games / 789bingo）+ 三行开关（图标、名称、开关、最后修改人 / 时间）。
- 修改：切换开关 → 点「保存」→ 二次确认弹窗列出变更（如 `Facebook：显示 → 隐藏`）→ 确认后即时生效。
- 初始值：上线时三个都为「显示」（与现网一致）。
- 操作日志：页面下方，列 时间（GMT+8）/ 操作人 / 站点 / 变更内容（旧值 → 新值），保留 180 天。
- 权限码（cate=3）：查看、修改（编号待后端分配），服务端校验。

## 4. 接口
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/front/config/thirdLogin` | 前台读取，返回 `{google, facebook, telegram}` 布尔值，按请求域名识别站点，不需登录 |
| GET | `/api/admin/config/thirdLogin?site=` | 后台读取，含最后修改人 / 时间 |
| POST | `/api/admin/config/thirdLogin` | 后台保存，入参 `site, google, facebook, telegram`；写操作日志 |
| GET | `/api/admin/config/thirdLogin/logs` | 操作日志分页 |

前台接口可缓存，但保存后须在 1 分钟内生效。

## 5. 验收要点
1. 逐个关闭三个按钮、两两组合、全部关闭，H5 / iOS / Android 显示符合 L1–L4。
2. 关闭后直接调用对应登录接口被拒绝；重新开启后可正常登录。
3. 789games 改配置不影响 789bingo。
4. 无修改权限的账号看不到保存按钮，直接调接口被拒。
5. 每次保存产生一条日志，旧值 / 新值正确。

## 6. 待确认

2. 是否需要配置按钮顺序（默认不做）。— 产品
