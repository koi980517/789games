# 白名单转盘 · 需求说明 v0.6

## 1. 背景与目标

运营需要给指定用户（召回、补偿、VIP 关怀等）直接发放转盘次数，不要求用户先充值。

现有【老用户充值转盘】的次数来自充值。现网虽然有“白名单奖励档位”，但它是按手机号命中、换一套档位，用户仍然要充值才能获得次数，满足不了这个场景。

本需求新增独立活动【白名单转盘】：

- 配置、预算、统计都和【老用户充值转盘】分开；
- 原老用户充值转盘保持不变。

## 2. 范围

| 包含 | 不包含 |
|---|---|
| 活动中心新增「白名单转盘」菜单，含活动配置、活动统计两个页签（白名单在活动配置内导入） | 修改原老用户充值转盘 |
| 转数设置、多转盘概率、流水指定游戏 | 未登录用户的转盘（不复刻登录前盘面） |
| 在创建 / 编辑页按手机号 CSV 导入白名单（沿用现有导入逻辑） | 按手机号导入 |
| 前台入口、获得次数提示、10 格转盘、中奖弹窗 | 返水奖励 |

## 3. 后台

### 3.1 活动列表（页签：活动配置）

- **筛选**：活动名称、创建人、状态。
- **列**：序号、活动编号、活动名称、活动类型、开始时间、结束时间、创建时间、活动总预算、已使用预算、白名单人数（新增）、已抽次数（新增）、创建人、状态开关、操作。
- **操作**：
  - 修改；
  - 删除（新增）：
    - 只有「关闭」状态、且没有未使用次数的活动可以删除，否则按钮置灰，悬停提示原因；
    - 删除前二次确认；
    - 软删除：列表不再显示，发放记录、抽奖明细、统计和操作日志都保留可查。
- 状态开关关闭后，已发放未使用的次数不能抽，前台入口隐藏。

### 3.2 创建 / 编辑活动

| 分组 | 字段 | 说明 |
|---|---|---|
| 展示 | 活动展示开关 | 开启后，剩余次数 > 0 的白名单用户才看得到入口；未登录用户一律不展示 |
| 基础 | 活动名称* | 必填 |
| 基础 | 活动开始时间* / 结束时间* | GMT+8；活动结束后未使用次数自动失效 |
| 基础 | 领取方式 | 手动领取 / 自动发放 |
| 基础 | 是否需要 KYC | 沿用现网规则 |
| 奖励 | 奖池总预算 | 留空表示不限 |
| 奖励 | 转数设置、转盘概率设置（多转盘） | 见 3.3 |
| 流水 | 彩金提现所需流水倍数 / 是否含奖金 / 计入流水的游戏 | 见 3.3.3 |
| 文案 | 奖励弹窗文案 | 支持 {bonus} |
| 文案 | 获得次数提示文案 | 支持 {count} {max}；留空则不弹 |

**与现网相比去掉的字段**：

- 是否需要有过充值记录、人群范围、充值渠道、首次 / 非首次充值档位（v0.5 起不做付费转，相关配置全部移除）；
- 白名单奖励档位；
- 流水“是否包含本金”、首次 / 非首次流水。

### 3.3 转数设置与转盘配置（v0.5，Koi 11-10 定）

v0.5 起全部为免费转，移除「付费」类型及其充值配置（充值记录、人群范围、充值渠道、首次 / 非首次档位、含本金流水）。

#### 3.3.1 转数设置

| 列 | 说明 |
|---|---|
| 转次 | 第 1 转、第 2 转……最多 10 转，至少 1 转，可新增 / 删除 |
| 使用转盘 | 下拉选择「免费转盘1 / 免费转盘2 / …」 |
| 解锁条件 | 第 1 转：进入白名单后即可转；之后：上一转完成即可转 |
| 单转最高奖 / 期望 | 取所选转盘的最高金额、期望成本 |

默认 3 转：第 1、2 转用免费转盘1，第 3 转用免费转盘2。页面实时显示单人最高成本、期望成本。

#### 3.3.2 转盘设置（多转盘，每个转盘独立奖励 + 概率）

- 每个转盘是一套独立的 **10 格奖励金额 + 中奖概率**（整数，合计 100%，0 = 只展示不命中），顺时针从顶部开始，第 1 格为大奖格。
- 转盘以卡片并排展示，**每个转盘一种底色**（蓝 / 橙 / 绿 / 紫 / 粉），卡片头显示名称（可改）和「第 x 转使用」；转数设置里对应行用同一底色，便于对照。
- 「+ 新增转盘」最多 5 个，新转盘默认复制上一个转盘的奖励和概率。被转数设置引用的转盘、或只剩 1 个转盘时不能删除（点删除提示原因）。
- 卡片底部显示合计、期望、最高。前台转到某一转时，盘面显示该转使用转盘的 10 格金额。
- 默认：免费转盘1 = 7,890 / 789 / 78.9 / 2.34 / 1.23 / 4.56 / 12.3 / 23.4 / 45.6 / 7.89，概率 0/0/0/30/35/20/5/0/0/10（期望 ₱3.45，最高 ₱12.3）；免费转盘2 = 7,890 / 888 / 188 / 88 / 58 / 38 / 28 / 18 / 12.3 / 8.8，概率 0/1/4/10/15/20/20/15/10/5（期望 ₱51.47，最高 ₱888）。

#### 3.3.3 流水要求

| 字段 | 说明 |
|---|---|
| 彩金提现所需流水倍数 | 默认 1 倍；稽核流水 = 中奖金额 × 倍数 |
| 稽核流水是否包含奖金 | 是 / 否 |
| 计入流水的游戏 | 全部游戏 / 指定游戏类别 / 指定游戏 |
| 指定游戏类别 | 6 类多选：Slots（电子）、Casino（真人）、Poker（棋牌）、Bingo（宾果）、Arcade（街机）、Fishing（捕鱼）；类别下新上架游戏自动计入 |
| 指定游戏 | 「选择游戏」弹窗（复用返水活动）：游戏类型 → 游戏厂商 → 具体游戏 三级勾选，上级联动下级；按名称或游戏 ID 搜索；只看已选；显示「已选 N 款」；确定后页面列出所选游戏及 ID，保存提交游戏 ID |

只有范围内游戏的有效投注计入该活动彩金的流水。

**保存校验**：每个转盘 10 格金额 > 0、概率合计 = 100%、名称非空、被至少 1 转使用；指定类别至少 1 类；指定游戏至少 1 款。保存前二次确认（显示每转用的转盘、单人最高 / 期望成本、流水范围），修改后已发未用次数按新配置抽，写操作日志。

### 3.3.4 预算告警与自动关闭

| 项 | 规则 |
|---|---|
| 顶部预算告警 | 接入后台顶部现有「预算告警」（`/api/admin/msg/get` 的 budgetAlertNum + `/api/admin/msg/budgetAlert/list`）：预算消耗 ≥ 全局阈值（现网 budgetAlertPercent = 70%）时进入告警列表，活动类型名新增 `whitelistSpin` = 「白名单转盘活动」，显示活动名和消耗率，可单条 / 全部关闭 |
| 预算不足自动关闭 | 剩余预算 < 当前最小奖励（所有被使用转盘中概率 > 0 的最小金额，默认 ₱1.23）时，活动自动关闭：状态开关变关闭、前台入口隐藏、未使用次数不可抽；写操作日志；列表在状态下标记「预算不足自动关闭」。补充预算后可手动重新开启 |
| 不限预算 | 奖池总预算为空时不告警、不自动关闭 |

### 3.3.5 权限（权限管理 › 角色权限）

在「活动中心 1014」下新增节点 **白名单转盘 101419**（现网 101401–101418 已占用）：

| 权限码 | 名称 |
|---|---|
| 10141901 | 活动配置-查看 |
| 10141902 | 新增 / 修改活动 |
| 10141903 | 开启 / 关闭活动 |
| 10141904 | 删除活动 |
| 10141905 | 白名单导入 |
| 10141906 | 已导入名单下载 |
| 10141907 | 活动统计-查看 |
| 10141908 | 活动统计-导出 |

服务端按权限码校验；无「查看」权限时菜单不显示；改权限后重新登录生效。顶部预算告警沿用现有权限。

### 3.4 白名单名单（在创建 / 编辑页内，不再单独设页签）

位置：创建 / 编辑页「转数设置」下方。沿用现有白名单导入逻辑（老用户充值转盘 / 登录送彩金白名单同款）。

| 项 | 说明 |
|---|---|
| 名单状态 | 共 N 个手机号（未注册 x · 已注册生效 y）· 最近更新时间 · 操作人；未保存时显示“活动未保存，暂无名单” |
| 导入文件 | 仅支持 CSV，首行表头 `phone`，每行 1 个 09 开头 11 位手机号；**须先保存活动**，未保存点击提示「请先保存活动后再导入白名单」 |
| 模板下载 | 下载 phone 模板 |
| 已导入文件下载 | 有名单后出现，导出 phone + 状态 |
| 导入结果 | 总行数 / 有效 / 无效 / 文件内重复 / 插入 / 已存在 + BatchId |

规则：
- 名单内每个用户获得 1 轮转数（按「转数设置」第 1–N 转，每转用指定转盘）。
- 未注册手机号注册后自动生效；同一手机号重复导入不重复发放；多次导入为追加。
- 保存成功弹窗提供「去导入白名单」，直接定位到本区域。
- 原「白名单发放」页签（单个发放、自定义次数、作废、发放记录）取消。

### 3.5 活动统计

- **筛选**：活动、会员账号、User ID、次数类型、领取时间，支持导出。
- **汇总**：发放人数、有效发放次数（含作废 / 失效数）、已抽次数和使用率、领取总额、预算使用、未使用次数的最高成本。
- **按次数类型统计**：发放次数、已抽次数、各格实际命中分布、领取总额、人均。
- **领取明细**：在现网字段基础上新增「次数类型」「发放记录ID」两列。导出 ≥1 万条时走异步。

## 4. 前台 H5

1. **入口**：只有剩余次数 > 0 的白名单用户能看到首页悬浮入口（转盘图标，显示 ×N）；未登录或不在白名单的用户不展示。
2. **获得次数提示**：发放后用户首次进入首页时弹出，每个发放批次只弹 1 次。协议弹窗优先于转盘弹窗。
3. **转盘页**：
   - 样式：紫金主题，10 格，标题 LUCKY SPIN，副标题 “Mega Jackpot up to {10 格最大金额}”；
   - 盘面元素：顶部指针，中心 GO 按钮，第 1 格紫底高亮；左上角为返回图标（回到首页），不再使用底部关闭按钮 ×；
   - 底座顶部：显示 Remaining spins，即所有记录的剩余次数之和（不再单独展示次数类型和到期时间）。
   - 底座主体：**真实中奖记录无限轮播**。
     - 数据：本活动最近 30 条真实中奖记录（不造假数据），账号脱敏为前 3 位 + *** + 后 4 位，显示 “xxx***1234 just won ₱金额”；
     - 展示：一次显示 2 条，每 2.2 秒向上滚动 1 条，滚到末尾无缝回到开头；≥ ₱789 的金额加大高亮；
     - 刷新：进入页面时拉取，之后每 60 秒刷新一次；用户自己抽中后立即插到最前面；
     - 无记录时显示 “Be the first to win!”。
4. **抽奖**：
   - 点 GO 后，接口按当前次数类型、在同类型的格子里按概率返回命中的格子和金额；
   - 前端转动后停在该格。
5. **中奖弹窗**：标题 LUCKY SPIN REWARDS，显示金额；关闭弹窗后入账。还有剩余次数时显示 “Spin Again (n)”，没有时显示 “Play Now”。
6. **异常状态**：活动关闭、已结束或预算用完时，提示 “This event has ended”。
7. **按钮样式**：
   - 主按钮：绿色渐变胶囊；
   - 次要按钮：亮面绿色、8px 圆角。

## 5. 验收要点

- 第 N 转只按该转指定转盘的概率出结果；抽 100 次分布接近配置，概率为 0 的格子（包括默认大奖 ₱7,890）不会被命中。
- 修改「转数设置」里某转使用的转盘后，未抽的次数按新转盘抽。
- 转盘被引用时不可删除；只剩 1 个转盘时不可删除；转到某一转时前台盘面金额 = 该转转盘的 10 格金额。
- 预算消耗到 70% 时顶部「预算告警」+1，并在告警条里出现「白名单转盘活动」；剩余预算 < 最小奖励时活动自动关闭。
- 无对应权限码的账号看不到菜单 / 按钮，接口返回无权限。
- 流水：指定类别 / 指定游戏之外的游戏投注不计入该彩金流水；类别下新上架游戏自动计入。
- 抽奖过程中被打断（如生物识别弹窗、断网），次数已经扣减，结果可以在记录中查到（参考 -6250）。
- 白名单导入：未保存活动不能导入；重复手机号计入“已存在”，不重复发放。
- 删除按钮：开启中的活动或有未使用次数的活动不可删除；删除后记录仍可查询。
- 底座轮播只显示本活动的真实中奖记录，账号已脱敏；记录数 ≤ 2 时不滚动，0 条时显示 Be the first to win!。
- 所有时间按 GMT+8，验收覆盖 00:00 前后的跨天场景。
- 新按钮配置操作权限码，并在服务端校验。

3. 预算用完后，已发放未使用的次数是停止抽奖，还是照常发奖。
4. 单次导入上限（原型暂定 5,000 行）、转盘个数上限（暂定 5 个）。
5. 是否要求用户是老用户（充值 ≥1），冻结 / 命中风控的账号是否拦截。
6. 与老用户充值转盘同时有次数时，入口和弹窗的优先级。
8. 是否需要按转盘分别设置流水倍数（目前全活动统一）。
7. 只在 789games 生效，还是两站都上。
