# 白名单转盘 · 需求说明 v0.3

## 1. 背景与目标

运营需要给指定用户（召回、补偿、VIP 关怀等）直接发放转盘次数，不要求用户先充值。

现有【老用户充值转盘】的次数来自充值。现网虽然有“白名单奖励档位”，但它是按手机号命中、换一套档位，用户仍然要充值才能获得次数，满足不了这个场景。

本需求新增独立活动【白名单转盘】：

- 配置、预算、统计都和【老用户充值转盘】分开；
- 原老用户充值转盘保持不变。

## 2. 范围

| 包含 | 不包含 |
|---|---|
| 活动中心新增「白名单转盘」菜单，含活动配置、白名单发放、活动统计三个页签 | 修改原老用户充值转盘 |
| 盘面 10 格配置（免费 / 充值） | 未登录用户的转盘（不复刻登录前盘面） |
| 按 User ID 单个 / 批量发放次数，以及发放记录、作废 | 按手机号导入 |
| 前台入口、获得次数提示、10 格转盘、中奖弹窗 | 返水奖励 |

## 3. 后台

### 3.1 活动列表（页签：活动配置）

- **筛选**：活动名称、创建人、状态。
- **列**：序号、活动编号、活动名称、活动类型、开始时间、结束时间、创建时间、活动总预算、已使用预算、已发放次数（新增）、已抽次数（新增）、创建人、状态开关、操作。
- **操作**：
  - 修改；
  - 发放：跳到「白名单发放」页签，并带上该活动；
  - 删除（新增）：
    - 只有「关闭」状态、且没有未使用次数的活动可以删除，否则按钮置灰，悬停提示原因；
    - 删除前二次确认；
    - 软删除：列表不再显示，发放记录、抽奖明细、统计和操作日志都保留可查。
- 状态开关关闭后，已发放未使用的次数不能抽，前台入口隐藏。

### 3.2 创建 / 编辑活动

| 分组 | 字段 | 说明 |
|---|---|---|
| 展示 | 活动展示开关 | 开启后，剩余次数 > 0 的白名单用户才看得到入口；未登录用户一律不展示 |
| 基础 | 活动名称* | 必填 |
| 基础 | 活动开始时间* / 结束时间* | GMT+8；活动结束后未使用次数自动失效 |
| 基础 | 领取方式 | 手动领取 / 自动发放 |
| 基础 | 是否需要 KYC | 沿用现网规则 |
| 奖励 | 奖池总预算 | 留空表示不限 |
| 奖励 | 盘面 10 格配置 | 见 3.3 |
| 提现 | 免费次数彩金流水倍数 / 是否含奖金 | 默认 1 倍 |
| 提现 | 充值次数彩金流水倍数 / 是否含奖金 | 默认 2 倍 |
| 文案 | 奖励弹窗文案 | 支持 {bonus} |
| 文案 | 获得次数提示文案 | 支持 {count} {max}；留空则不弹 |

**与现网相比去掉的字段**：

- 白名单奖励档位，以及按手机号导入；
- 流水“是否包含本金”。

### 3.3 转数设置与转盘配置（v0.4，Koi 11-10 定）

**转数设置**（奖池预算下方）：逐转设置每个白名单用户一轮能转几次、每一转是「免费」还是「付费」，最多 10 转，至少 1 转，按顺序转。默认 3 转：免费 → 免费 → 付费。

| 列 | 说明 |
|---|---|
| 转次 | 第 1 转、第 2 转…… |
| 类型 | 免费 / 付费，可切换 |
| 解锁条件 | 免费：第 1 转发放后即可转，之后上一转完成即可转；付费：上一转完成，且充值到账并命中下方充值档位 |
| 使用配置 | 免费 → 免费转盘配置；付费 → 付费转盘配置（充值配置表） |

页面实时显示每人共几转（免费 x / 付费 y）和单人最高成本。

**免费转盘配置**（有免费转时出现；没有免费转时只显示「盘面 10 格金额」）

- 盘面固定 10 格，顺时针从顶部开始，第 1 格为大奖格；金额即前台盘面显示金额。
- 每格配置「免费中奖概率」，合计 100%，0 = 免费转抽不到。默认：₱2.34 30%、₱1.23 35%、₱4.56 20%、₱12.3 5%、₱7.89 10%，其余 0；免费转期望 ₱3.45 / 次，最高 ₱12.3。
- 每格显示「被付费档位引用」，便于核对。
- 免费转彩金流水倍数 + 是否含奖金。

**付费转盘配置 · 充值配置**（有付费转时出现，平移老用户充值转盘的充值配置表）

| 字段 | 说明 |
|---|---|
| 是否需要有过充值记录 | 是 / 否 |
| 人群范围 | 用户充值次数 ≥ / = / ≤ N |
| 充值渠道 | PayMongo / Traxion Pay / PayCools / GCASH 多选，至少 1 个 |
| 奖励档位 | 每档 = 首次 / 非首次 + 充值金额区间（最大值空 = 无穷大）+ 奖励金额 1、2（**从盘面 10 格中选**）+ 整数概率（合计 100%），可新增 / 删除 |
| 首次 / 非首次流水 | 各自配置倍数、是否含本金（充值金额）、是否含奖金 |

默认档位：首次 500–1,000（₱23.4 80% / ₱45.6 20%）、1,001–5,000（₱45.6 70% / ₱78.9 30%）、5,001+（₱78.9 80% / ₱789 20%）；非首次 500–1,000（₱12.3 80% / ₱23.4 20%）、1,001–5,000（₱23.4 70% / ₱45.6 30%）、5,001+（₱45.6 80% / ₱789 20%）。

付费转逻辑：用户转到付费转时需先充值；充值到账后按「首次 / 非首次 + 金额」匹配档位，按该档位的奖励和概率抽奖，转盘停在对应格；一笔充值解锁 1 个付费转。

**保存校验**：10 格金额 > 0；有免费转时免费概率合计 = 100%；有付费转时渠道 ≥ 1、每档区间合法且概率合计 = 100%、同类型（首次 / 非首次）区间不重叠。修改后已发未用次数按新配置抽，二次确认并写操作日志。

### 3.4 白名单发放（新增页签）

**选择活动**：下拉列出全部白名单转盘活动，默认选中最近创建的活动；切换后剩余预算、活动时间和发放记录跟着切换。活动未开启或已关闭时提示“发放的次数在开启后才能抽”。创建活动保存成功后可点「去发放」直接进入。

**单个发放**

| 字段 | 规则 |
|---|---|
| User ID* | 输入后显示会员账号、充值次数和账号状态 |
| 发放方式* | 按活动转数（默认，发放 1 轮 = 转数设置里的全部转（默认免费、免费、付费））/ 自定义 |
| 转盘次数* | 自定义时填写，1–10 次 |
| 次数类型* | 自定义时选择：免费 / 付费（充值解锁） |
| 备注 | 选填 |

**预算校验**：按“次数 × 该类型最高奖”预估最高成本，超过剩余预算时拦截。

**批量导入**

- **模板 CSV**：`userId, spinCount, spinType, remark`，其中 `spinType` 填 `TEMPLATE`（按活动转数发放 spinCount 轮）、`FREE` 或 `PAID`。
- **数量限制**：单次最多 5,000 行。
- **导入预览**：显示总行数、有效、无效（User ID 不存在、类型不合法、次数超限）和文件内重复（重复行合并累加），以及预估最高成本。
- 无效明细可以下载，确认后才发放。

**发放记录**

- **筛选**：User ID、次数类型、状态、操作人、操作时间，支持导出。
- **列**：记录ID、User ID、会员账号、发放次数、次数类型、已使用、剩余、中奖结果、状态、来源（单个 / 批量批次号）、备注、操作人、操作时间、操作（明细 / 作废剩余）。
- **状态**：未使用 / 使用中 / 已用完 / 已作废 / 已失效。
- **同一用户多次发放**：同一个 User ID 可以多次发放，每次生成一条独立记录，按发放时间先发先用。
- **作废剩余**：只作废还没使用的次数，已中奖的金额不回收；必须填写原因，并写入操作日志。

**记录详情**：显示基本信息、可命中的格子及其概率、流水倍数、每一次抽奖的明细（时间、金额、领取状态、稽核流水、端），以及操作日志。

### 3.5 活动统计

- **筛选**：活动、会员账号、User ID、次数类型、领取时间，支持导出。
- **汇总**：发放人数、有效发放次数（含作废 / 失效数）、已抽次数和使用率、领取总额、预算使用、未使用次数的最高成本。
- **按次数类型统计**：发放次数、已抽次数、各格实际命中分布、领取总额、人均。
- **领取明细**：在现网字段基础上新增「次数类型」「发放记录ID」两列。导出 ≥1 万条时走异步。

## 4. 前台 H5

1. **入口**：只有剩余次数 > 0 的白名单用户能看到首页悬浮入口（转盘图标，显示 ×N）；未登录或不在白名单的用户不展示。
2. **获得次数提示**：发放后用户首次进入首页时弹出，每个发放批次只弹 1 次。协议弹窗优先于转盘弹窗。
3. **转盘页**：
   - 样式：紫金主题，10 格，标题 LUCKY SPIN，副标题 “Mega Jackpot up to {10 格最大金额}”；
   - 盘面元素：顶部指针，中心 GO 按钮，第 1 格紫底高亮；左上角为返回图标（回到首页），不再使用底部关闭按钮 ×；
   - 底座顶部：显示 Remaining spins，即所有记录的剩余次数之和（不再单独展示次数类型和到期时间）。
   - 底座主体：**真实中奖记录无限轮播**。
     - 数据：本活动最近 30 条真实中奖记录（不造假数据），账号脱敏为前 3 位 + *** + 后 4 位，显示 “xxx***1234 just won ₱金额”；
     - 展示：一次显示 2 条，每 2.2 秒向上滚动 1 条，滚到末尾无缝回到开头；≥ ₱789 的金额加大高亮；
     - 刷新：进入页面时拉取，之后每 60 秒刷新一次；用户自己抽中后立即插到最前面；
     - 无记录时显示 “Be the first to win!”。
4. **抽奖**：
   - 点 GO 后，接口按当前次数类型、在同类型的格子里按概率返回命中的格子和金额；
   - 前端转动后停在该格。
5. **中奖弹窗**：标题 LUCKY SPIN REWARDS，显示金额；关闭弹窗后入账。还有剩余次数时显示 “Spin Again (n)”，没有时显示 “Play Now”。
6. **异常状态**：活动关闭、已结束或预算用完时，提示 “This event has ended”。
7. **按钮样式**：
   - 主按钮：绿色渐变胶囊；
   - 次要按钮：亮面绿色、8px 圆角。

## 5. 验收要点

- 只发放免费次数的用户抽 100 次，结果只落在免费格，分布接近配置的概率；充值次数同理。
- 概率为 0 的格子（包括默认的大奖 ₱7,890）永远不会被命中。
- 同时有免费、充值两条记录时，按发放时间先发先用，底座剩余次数等于两条之和。
- 抽奖过程中被打断（如生物识别弹窗、断网），次数已经扣减，结果可以在记录中查到（参考 -6250）。
- 作废后剩余次数立即不可用；活动结束后状态变为「已失效」。
- 删除按钮：开启中的活动或有未使用次数的活动不可删除；删除后记录仍可查询。
- 底座轮播只显示本活动的真实中奖记录，账号已脱敏；记录数 ≤ 2 时不滚动，0 条时显示 Be the first to win!。
- 所有时间按 GMT+8，验收覆盖 00:00 前后的跨天场景。
- 新按钮配置操作权限码，并在服务端校验。

## 6. 待确认

2. 免费 / 充值次数是否需要不同的有效期或展示文案。
3. 预算用完后，已发放未使用的次数是停止抽奖，还是照常发奖。
4. 单次和单人累计发放的上限（原型暂定单次 ≤10、批量 ≤5,000 行）。
5. 是否要求用户是老用户（充值 ≥1），冻结 / 命中风控的账号是否拦截。
6. 与老用户充值转盘同时有次数时，入口和弹窗的优先级。
7. 只在 789games 生效，还是两站都上。
