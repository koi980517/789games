# 现网读取：老用户充值转盘（QA 后台，2026-11-10）

## 页面与接口

- **菜单**：活动中心 › 老用户充值转盘。
- **路由**：`#/old-user-spin-activities`。
- **页签**：活动配置｜活动统计。
- **接口**：`/api/admin/activity/oldUserRechargeSpin/*`，activityType 为 `OLD_USER_RECHARGE_SPIN`。

## 活动列表

- **筛选**：活动名称、创建人、状态。
- **列**：序号 / 活动编号 / 活动名称 / 活动类型 / 活动开始时间 / 活动结束时间 / 创建时间 / 活动总预算 / 活动已使用预算 / 创建人 / 状态 / 操作（修改）。

## 创建表单（组件 old-user-spin-config-form）

**展示与基础**

- 活动展示开关：控制未登录用户是否能看到活动入口。
- 活动名称：唯一有必填校验的字段。
- 活动开始时间、结束时间。
- 领取方式 `receiveType`：手动领取 / 自动发放。
- 是否需要 KYC `needKyc`。
- 是否需要有过充值记录 `needRecharge`。

**参与范围**

- 人群范围 `rechargeCountCondition`：用户充值次数（relation，默认 gte 1）。
- 充值渠道 `rechargeChannels`：PayMongo / Traxion Pay / PayCools / GCASH。

**奖励**

- 奖池总预算：留空表示不限金额。
- 奖励档位 `firstTimeRewards` / `nonFirstTimeRewards`：
  - 每档包含 `minRecharge` / `maxRecharge`；
  - 每档的 `rewardItems` 最多 2 个，每个是 amount + 整数 probability。
- 白名单奖励档位 `whitelistFirstTimeRewards` / `whitelistNonFirstTimeRewards`：结构同上。

**白名单导入**

- 接口：`/whitelist/importCsv`，模板为 `/whitelist/csvTemplate`。
- 文件：仅支持 CSV，模板只有一列 `phone`。
- 前提：必须先保存活动才能导入。
- 导入结果：新增 / 已存在 / 无效 / 文件内重复。

**奖励提现（流水）**

- 首次：流水倍数，是否包含本金，是否包含奖金。
- 非首次：流水倍数，是否包含本金，是否包含奖金。

**文案**

- 奖励弹窗文案，支持 `{bonus}`。

## 活动统计

- **筛选**：会员账号、领取时间。
- **功能**：导出，并显示领取总额。
- **列**：ID / 会员ID / 会员账号 / 活动类型 / 领取金额 / 日期 / 领取时间。

## 结论

现网“白名单”的作用是让名单内的手机号用户在充值时改用白名单档位，用户仍然需要充值才能获得次数，和本需求“后台直接发次数”不是一回事。因此白名单转盘作为独立活动来做。
